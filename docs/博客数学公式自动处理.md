# VS Code 博客数学公式自动处理

本项目继续使用 **Jekyll/Kramdown + al_math/MathJax**，无需安装新的渲染插件。

## 1. 日常使用

### 新建笔记：自动生成 Jekyll 表头

**GitHub 网页新建文件（无需输入快捷键）：** 在 `main` 分支的 `_posts` 目录创建 `YYYY-MM-DD-主题.md`。
提交后 GitHub Actions 会为缺少表头的文件自动生成 `layout: post`、文件名标题及北京时间。
即使文件是空白的，也会生成完整表头，并提交回仓库、触发网站发布；已有表头或科研正文不会被覆盖。
请在提交后查看 GitHub Actions 的 `Automatically create Jekyll post headers` 记录，而不是在提交前的编辑框中寻找自动填写内容。

**VS Code 新建文件（快捷插入）：** 仍可使用已有代码片段，不需要再复制下面这段 YAML 表头。新建笔记时：

1. 在 `_posts` 目录中新建 Markdown 文件，文件名沿用 `YYYY-MM-DD-主题.md` 格式，例如 `2026-10-21-catmap-05-knowledge-points.md`。
2. 将光标放在空白文件的第一行，输入 `jekyll-post`。
3. 按 **Tab**（如果未出现提示，按 `Ctrl+Space` 后选择“Jekyll 博客文章表头”）。

VS Code 会自动插入 `layout: post`、标题和当前日期时间；标题默认取当前文件名，可在插入时直接修改。该功能使用项目内的 `.vscode/markdown.code-snippets`，**无需安装扩展**。

> 仅在新建的空白笔记中插入一次；已有 Jekyll 表头的文章不要重复插入，以免产生重复的 Front Matter。

### GitHub 网页新建笔记：提交后自动填写表头

GitHub 仓库网页不支持 VS Code 的 `jekyll-post` 代码片段。现在可直接在 `_posts` 中新建 `YYYY-MM-DD-标题.md`，**不必先复制 YAML 表头**。

将空白笔记或只有正文的笔记提交到 `main` 后，`Deploy site` 工作流会在构建前检查此次提交新增或修改的 `_posts/*.md` 文件。对于**尚无表头**、且文件名符合 `YYYY-MM-DD-标题.md` 的文章，自动添加以下字段，并由 GitHub Actions 提交回 `main`：

- `layout: post`
- `title`：默认采用不带 `.md` 扩展名的完整文件名
- `date`：采用文件名中的日期，时区固定为 `+0800`；若为当天创建则采用构建时的北京时间，否则使用该日 `10:00:00`

此处理发生在**提交后**，不是在 GitHub 网页中输入或粘贴时立即显示。刷新仓库文件页面即可查看自动提交后的 YAML 表头。已有完整的表头保持原样，不覆盖用户填写的标题、日期和正文。


在 VS Code 编辑 `_posts/*.md` 时，可直接将明确独立成行的 LaTeX 公式粘贴到正文。推送 GitHub 后，Jekyll 构建前会自动为符合规则的公式补充 `$$` 定界符，**仅修改构建时内存中的内容，不修改、提交或覆盖原始 Markdown 文件**。

例如直接粘贴：

```latex
\boxed{\tau=\frac{1}{|\lambda|}}
```

生成网站时自动处理为：

```latex
$$
\boxed{\tau=\frac{1}{|\lambda|}}
$$
```

同样支持独立成行的 `\frac{...}{...}`、以 LaTeX 变量开头的等式，以及完整的 `aligned`、`gathered`、`cases` 等数学环境。
正文中的 MathJax 行内定界符 `\(...\)` 会在构建时转换为 Kramdown 兼容的 `$$...$$`；对于明确的括号内 LaTeX（如 `(k_{\mathrm B}T)`），
以及科学语境下的单字母符号（如“普朗克常数 `(h)`”），也会自动补充行内公式定界符。

**更推荐：** 在 Markdown 文件输入 `mathblock`，按 Tab 选中 VS Code 的代码片段，自动插入公式块的 `$$` 定界符。代码片段来自 `.vscode/latex.code-snippets`，不需要安装扩展。

## 2. 边界

- 已正确包围的独立公式块、代码围栏、行内代码及 Liquid 高亮代码保持原样；行内数学定界符会在构建时统一转换为 Kramdown 兼容格式。
- 无法明确识别边界的公式不会被猜测修改；请使用 `mathblock` 显式标记。
- 检测到已识别候选公式的花括号不匹配、环境未闭合、数学与中文说明混写等问题时，构建直接报错并指明文件位置，不静默修改物理含义。
- 此功能负责定界符与渲染流程，不负责判断公式推导、单位或科研结论是否正确。
- **VS Code 源文件不会自动改写**；自动化发生在 Jekyll 构建/网站发布阶段。

## 3. 验证

本地项目有 Ruby/Jekyll 依赖时：

```bash
bundle exec ruby test/research_math_guard_test.rb
bundle exec jekyll build
```

GitHub Actions 的 `Deploy site` 工作流在构建前运行上述回归测试；失败即停止该工作流的部署。测试涵盖公式中竖线不应变成 Markdown 表格、代码块保护、重复执行不产生变化与异常公式拒绝规则。
